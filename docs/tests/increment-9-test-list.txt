# Increment 9: unscoped protected folders - Test List

## Specifications
- Tools: `spotlight_query`, and `search` without a `folder`; both count as a scope containing ~/Downloads, ~/Documents and ~/Desktop, and carry increment 8's `unreadableFolders` for each one denied by macOS privacy protection (TCC)
- `search` with a `folder` keeps increment 8's behaviour unchanged
- Probe: all three protected folders are probed after the arguments are accepted and before the Spotlight query runs; a rejected argument returns its error and probes nothing
- Only a TCC denial adds an entry; a missing protected folder, a file-permission denial or any other read failure adds none
- Entry, order and output: as in increment 8, {"path": <expanded path>, "fix": <increment 7's TCC fix>}, ordered Downloads, Documents, Desktop, next to `paths` in structuredContent and in the JSON text block; no denied folder means no `unreadableFolders` key
- Error results are unchanged: a query Spotlight rejects returns its error with no structured content, even when a protected folder was found denied
- Output schema: unchanged; its `unreadableFolders` wording must not assume a searched folder, since the field now also appears on unscoped calls
- Acceptance tests start the server with a temporary home whose Downloads, Documents and Desktop are readable, so a run never probes the real home, never prompts, and does not depend on the machine's privacy settings
- Tests cannot make TCC deny a folder: server tests use a fake file system, and the real denial is checked by hand for both tools
