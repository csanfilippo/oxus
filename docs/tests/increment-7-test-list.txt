# Increment 7: protected folders - Test List

## Specifications
- Tool: `search` with a `folder`; `spotlight_query` and unscoped searches are unaffected
- Replaces increment 6's single "cannot read" error with two errors for a denied scope folder; not found, is a file, and package errors unchanged
- Denied by macOS privacy protection (TCC, POSIX `EPERM`): names the path and the fix: System Settings › Privacy & Security › Files and Folders › <folder>, granted to `oxus` if it is listed there, otherwise to the app that launched oxus
- <folder> is the protected folder containing the scope: Downloads for `~/Downloads` and anything inside it, likewise Documents and Desktop
- Denied by TCC outside `~/Downloads`, `~/Documents` and `~/Desktop`: names the path and a generic fix: System Settings › Privacy & Security, granted to `oxus` or the app that launched it, no folder setting named
- Denied by file permissions (POSIX `EACCES`): names the path and the missing read permission
- Any other read failure (e.g. `EIO`) keeps increment 6's error: the path and the reason macOS gives
- Paths named are the expanded paths, e.g. `/Users/me/Downloads` for `~/Downloads`; "inside" means inside the folder, not sharing its name prefix (`~/Downloads Archive` is outside `~/Downloads`)
- Adapter tests cannot make TCC deny a folder: the EPERM mapping is tested on a constructed error, and the real denial is checked by hand
