# Increment 3: search by kind - Test List

## Specifications
- Tool: `search` gains `kind` (string, optional), advertised as an `enum`: image, movie, audio, pdf, folder, application
- `name_contains` becomes optional; at least one of `name_contains` and `kind` is required
- Filters present in the same call are combined with AND
- Matching: each kind matches its content type on `kMDItemContentTypeTree`, so a parent type matches all subtypes (image → public.image, movie → public.movie, audio → public.audio, pdf → com.adobe.pdf, folder → public.folder, application → com.apple.application)
- Kind values are exact and lowercase: "Image" is an unknown kind
- Neither filter: result with isError and a message saying at least one of name_contains or kind is required
- Unknown or non-string `kind`: result with isError and a message that lists the accepted kinds
- Blank `name_contains` is still an error, even when `kind` is present
- Limit and output unchanged from increment 2; `spotlight_query` unchanged
- Spotlight port and adapter unchanged; acceptance tests rely on Finder.app's content type tree containing com.apple.application and not public.folder
