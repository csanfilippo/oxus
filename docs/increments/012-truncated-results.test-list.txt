# Increment 12: truncated results - Test List

## Specifications
- Tools: `spotlight_query` and `search`, which share `OxusResponse`
- Matches above `limit` add "truncated": true next to `paths`, in structuredContent and in the JSON text block; `paths` holds exactly `limit` paths
- Every match returned, including matches equal to `limit`, means no `truncated` key
- `truncated` and `unreadableFolders` are independent
- Output schema: both tools advertise `truncated` as an optional boolean, described as more matches existing than `paths` holds
- Input schema: the `limit` description, shared by both tools, says a cut-off result carries `truncated`, because some clients do not show output schemas to the model
- Error results are unchanged: no structured content
- `limit`: default, maximum and error messages unchanged; CoreServicesSpotlight caps MDQuery one result above `limit`, including at the maximum of 100, and the port tells the server that more matches exist
- Real Spotlight has enough system files to cut off at 100: `kMDItemFSName == "*.app"c` matches 399 under /System
- SpySpotlight must honour the same contract: at most `limit` paths, and a report that more matches exist
- The port returns SpotlightMatches, declared in OxusServer: the paths and whether more matches exist
