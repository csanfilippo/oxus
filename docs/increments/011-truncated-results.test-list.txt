# Increment 11: truncated results - Test List

## Specifications
- Tools: `spotlight_query` and `search`, which share `OxusResponse`
- Matches above `limit` add "truncated": true next to `paths`, in structuredContent and in the JSON text block; `paths` holds exactly `limit` paths
- Every match returned, including matches equal to `limit`, means no `truncated` key
- `truncated` and `unreadableFolders` are independent
- Output schema: both tools advertise `truncated` as an optional boolean, described as more matches existing than `paths` holds
- Error results are unchanged: no structured content
- `limit`: default, maximum and error messages unchanged; Spotlight stays capped one result above `limit`, including at the maximum of 100
- The port's way of reporting a cut-off is an open decision in the increment doc; each test below states behaviour, not its shape
