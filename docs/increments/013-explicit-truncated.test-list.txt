# Increment 13: explicit truncated - Test List

## Specifications
- Tools: `spotlight_query` and `search`, which share `OxusResponse`
- Every successful result carries `truncated` next to `paths`, in structuredContent and in the JSON text block
- `truncated` is true when matches exceed `limit`, false otherwise, including matches equal to `limit`
- `unreadableFolders` still appears only when there is something to report
- Output schema: both tools list `truncated` as a required boolean; `required` is `paths` and `truncated`
- The `truncated` description no longer says the key can be absent
- Input schema: the `limit` description, shared by both tools, says `truncated` is true when a result is cut off
- Error results are unchanged: no structured content
- The Spotlight port, SpotlightMatches and CoreServicesSpotlight are unchanged
